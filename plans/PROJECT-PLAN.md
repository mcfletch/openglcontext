| [HUD-DEBUG-OVERLAY.md](HUD-DEBUG-OVERLAY.md) | ✅ Complete | Screen furniture drawn over a live world, and the developer overlay that replaces the frame-rate display. **A HUD is not a panel**: the overlay stack is modal, which is right for a settings screen and wrong for a health bar, so a `HUDLayer` is a widget tree that fills the viewport, is laid out every frame, answers `widget_at()` with `None` and is drawn *under* any panel that is open. Placement is by **anchor** (`top-left` … `bottom-right`) plus an offset, because no row/column arithmetic describes “health in that corner, reticule in the middle” as well as naming the corner does; a child with no anchor still gets the whole layer and lays itself out as before. Widgets: `Crosshair` (**the reticule is a weapon's property** — shape, gap, arm length, thickness and a `spread` that widens with the weapon's accuracy, plus a hit mark), `BarMeter` (three threshold colours rather than a gradient, because a player reads a state and not a number), `Readout` (icon + number) and `MessageQueue` (newest first, each line on its own clock, fading in its alpha). **The developer overlay is fed by registered providers** — a callable returning name/value pairs — so a subsystem appears in it by registering rather than by anyone editing it; values are formatted centrally, a provider that raises becomes an `error` row instead of taking the frame down, and one with nothing to say is left out rather than drawn as an empty heading. Shipped providers: frame rate/time/viewport, renderer features + `passes/renderstats.py` frame counts (shapes, draws, instanced groups — **counted where the pass knows the answer; triangle counts deliberately absent rather than guessed**), camera and character-controller state, and a physics body/contact provider. **Retired**: `FrameCounter.Render` (fixed-function `glOrtho`/`glPushAttrib` in a core-profile renderer), its shader-side duplicate `shaderRenderFrameCounter`, and `FrameCounter.display`; Alt+F now toggles the overlay and `OPENGLCONTEXT_DISABLE_FPS_DISPLAY` decides whether it *starts* hidden, so the capture harness needed no change. `ScreenMixin` is a base of `Context` itself (every context has a frame rate) and `OverlayMixin` extends it, so HUD and panels are one list drawn in one batch. `Panel`'s children/skin/scaling/link machinery moved up into `widgets.RootWidget`, which a panel and a HUD layer are both kinds of. **Red/Green TDD: 93 tests with no GL** (anchors, reticule geometry, thresholds, message expiry, provider registration/ordering/formatting, laid-out rows, drawing order) **+ 7 against a real driver**. Docs: [docs/hud.html](../docs/hud.html). First customer: twitch's `twitchoglc.hud` |
